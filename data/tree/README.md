# 策略树 v0.1（决策表版）

> 结论先说：**不要建五维树，建决策表。树是查询出来的视图，表才是存储。**
> 五维全展开 ≈ 7000 节点，人维护不动；压成规则后是几百条，现在先落了 69 条。

## 七个维度

| 字段 | 取值 |
| :--- | :--- |
| `pot_type` | 翻前 / SRP / 3BP / 4BP / 多人 |
| `role` | IP-PFR / OOP-PFR / IP-caller / OOP-caller / BvB-SB / BvB-BB |
| `board_class` | 见 `board_classes.md`（如 `高A-低-彩`） |
| `street` | 翻前 / 翻牌 / 转牌 / 河牌 |
| `node_action` | 无（我先动）/ 对手过牌 / 对手小注 / 对手中注 / 对手大注 / 对手过牌加注 |
| `line` | 我是怎么走到这的：翻牌过牌→延迟 / 翻牌下注→持续 / 被过牌加注后 / 二枪 / 河牌（转牌、河牌必填） |
| `runout` | 转牌/河牌的变化类型：空白 / 高张 / 双高 / 成花 / 成顺 / 成对 |
| `capped` | 对手范围是否封顶：**是 / 否**。同一个「对手过牌」，他范围封顶和未封顶是两种打法 |
| `vs_type` | 对手倾向：常客 / 娱乐 / 过度诈唬型 / 下注不足型（剥削规则用，命中时优先于通用规则） |
| `status` | active / hold（已裁决并存）/ retired（已退役，不参与匹配） |
| `opp_pos` | UTG / HJ / CO / BTN / SB / BB（翻前必填，翻后多为 `*`） |
| `stack` | 100bb / 200bb / 50bb（多数 `*`） |

`*` = 通配。匹配时按**特异度**打分（命中的非通配字段数），最高的胜出；同分全部列出并标 ⚠ —— 那就是需要你裁决的冲突。

## 范围校准（重要）

规则查询前先问一句：**这两个位置对的翻前范围差多少？** 同一牌面 UTG 和 BTN 的答案可能相反。

```bash
python -m pokercoach.rangeboard 754r "UTG" "BB"
```

输出双方「两对及以上」的组合数与比值（≥1.4 倍可上大尺度，≤0.5 倍该降尺度）。范围库在 `pokercoach/preflop.py`，说明见 `策略树-范围校准.md`。

## 行动路径（path）

界面「⑬ 行动路径」用紧凑语法描述**怎么走到这一步**，一条路径可跨多街：

```
F:XX           翻牌 过牌-过牌
F:BC           翻牌 我下注-对手跟
F:XBRC         翻牌 我过牌 → 对手下注 → 我加注 → 对手跟
F:BXRC         翻牌 我下注 → 对手过牌-加注 → 我跟
F:BC|T:BC      翻牌 下注-跟 → 转牌 下注-跟（二枪）
F:BC|T:        翻牌 下注-跟 → 决策点在转牌
```

- `F` 翻牌 / `T` 转牌 / `R` 河牌
- `X` 过牌 / `B` 下注 / `C` 跟注 / `R` 加注
- **以冒号结尾**的段表示「决策点在这一街」

**引擎规则**：查询带 `path` 时，规则必须满足「路径前缀匹配」，且路径越长加分越多。
查询不带 `path` 时退回旧字段匹配（向后兼容）。

**已知路径 → line 映射**：F:XX→翻牌过牌→延迟、F:BC→翻牌下注→持续、F:XBRC→我XR后被跟注、
F:BXRC→被过牌加注后、F:XX|T:XX→转牌双方过牌、F:BC|T:BC→二枪。

「→ 打到下一街」按钮会自动把路径续写一段（如加上 `|T:`）。

## 怎么打开（三种）

**① 复盘台「策略树」标签页（推荐，最新）**
双击桌面「扑克复盘台」→ 顶部「策略树」（6 个主导航之一）→ 选底池/角色/牌面/街/对手动作 → 出 13×13 矩阵。
按比赛流程从上到下选：**筹码深度 → 我在哪 → 对手在哪 → 谁先加注 → 底池类型 → 牌面 → 街道 → 对手动作**，

每格左边按频率填色、右边留深色底，中间写百分比；点格子看详情。改任何一项都会自动重查。
接口：`GET /api/tree?pot=SRP&role=IP-PFR&board=A72r&street=翻牌&action=对手过牌`

## 已知缺口（如实）

1. **3BP-OP 的桶是从频率反推的**（K20–K30），不是课程原表——课程只给了每类牌面的总频率与尺度。
2. **BvB 的桶表复用**：K10/K11 是「延迟/持续」的桶，翻牌 cbet 的桶（K8/K9）只覆盖了两种牌面。
3. **河牌只有 5 条规则**，基本没铺开。
4. **翻前只有 9 条**，且只有「vs 3bet」一条线；开池范围、vs open、4bet 树都没进。
5. **桶表里「其他」是兜底值**，不是真实策略，别当真。

## 怎么加一条规则

1. 先查 `board_classes.md` 有没有对应的牌面类；没有就**先加类，再加规则**。
2. 在 `rules.csv` 追加一行：ID 顺延、五维定位、尺度、频率、桶表。
3. 如果它带来新的桶分布，去 `buckets.csv` 加一整张表（`table_id` 不能和现有重复）。
4. 跑 `python3 lookup.py --test`；再补一个用例把它钉住。

## 两条设计铁律

1. **牌面用类别，不用具体三张**。否则 1755 种翻牌永远填不完。
2. **每条规则必须带 source 与 conf**。不标源的规则，半年后没法判断该不该信。
