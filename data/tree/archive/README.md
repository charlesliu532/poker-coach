| 原规则 | SRP·IP-PFR·高A-高-彩·翻牌·对手过牌 → **150% 超池**，全范围极化（K45） |
| 来源 | Overbankroll 3.0 |

### R111 · 长剑 7x（翻牌 XR）

| 项 | 内容 |
| :--- | :--- |
| 原规则 | SRP·OOP-caller·中-公对·翻牌·对手小注 → **7x+ 加注**（K75） |
| 来源 | 胡萝卜《战争武器 3·利剑》 |
| 退役原因 | **Smash M09 全 13 讲零出处**：XR 尺码只出现 3x（L04）、3–4x（L06）、加注到 50% Pot（L07），最大 4 倍。且 L07 的方法论是「**能让对手犯错的最小尺度**」，与 7x 直接相悖 |
| 取代者 | **R110**（短剑 3.5x，K74）——升为**唯一默认 XR 尺码** |
| 佐证 | 3x / 3–4x / 最小有效 三条证据都指向同一区间，3.5x 落在中间 |
| 备注 | 胡萝卜「长剑」本身没错——它针对的是「公对面/双高张」，那类面确实该加得更重。但 Smash 认为**公对面是高频过牌面**（PFR 过牌率≈60%），XR 不是主角。两种框架的分歧保留在此 |

## 什么该进归档、什么该退役

| 情况 | 处理 |
| :--- | :--- |
| 被更好的来源取代（数字被证伪） | **退役** + 写清取代者 |
| 两个来源各有道理、还没打完样本 | **并存（hold）**，留在主树 |
| 分类粒度不够导致的假冲突 | **不退役**，改数据模型（如加 `board_exact` / `capped` 字段） |
| 整块打法被新框架推翻 | **退役整组** + 归档整组桶表 |

## 恢复方法

想让某条复活：

```bash
# 1. 从归档 csv 找到那行，把 status 改回 active 追加进 rules.csv
# 2. 如果桶表也归档了，把 archive/退役桶表-KXX.csv 的行并回 buckets.csv
# 3. 重建：python3 data/tree/build_view.py
```

**注意**：退役规则不会自动复活，且与原取代者会形成并存——恢复前先确认取代者是否还成立。
